# 메이플스토리 보스 파티 봇

길드/친목 파티가 디스코드에서 **주간 보스 파티 일정을 잡고, 그 주에 번 결정석 수익을 정산**하는 봇입니다.

넥슨 Open API를 쓰지 않습니다. 클리어 여부는 `/클리어` 로 직접 입력합니다.
모든 시각은 **한국 시간(KST)** 기준이며, DB에는 UTC로 저장하고 출력할 때 KST로 바꿉니다.

## 설치

Python 3.11 이상이 필요합니다.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[dev]"
```

`.env.example` 을 `.env` 로 복사해 채웁니다.

```
DISCORD_TOKEN=봇_토큰
DATABASE_URL=sqlite:///maple_boss_bot.db
LOG_LEVEL=INFO
GUILD_ID=            # 개발 중 슬래시 커맨드를 즉시 반영할 서버 ID (비우면 전역 등록)
```

DB 스키마를 만듭니다.

```bash
alembic upgrade head
```

## 봇 토큰과 권한

1. [Discord Developer Portal](https://discord.com/developers/applications) 에서 New Application
2. **Bot > Reset Token** 으로 토큰 발급 → `.env` 의 `DISCORD_TOKEN` 에 넣기
3. **OAuth2 > URL Generator** 에서 아래를 고르고 나온 링크로 초대

| 항목 | 값 |
| --- | --- |
| Scopes | `bot`, `applications.commands` |
| Bot Permissions | `Send Messages`, `Embed Links`, `Read Message History` |

**특권 인텐트(Privileged Gateway Intents)는 필요 없습니다.** 슬래시 커맨드만 쓰기 때문에
Message Content, Server Members, Presence 모두 꺼둔 채로 동작합니다.

`.env` 는 `.gitignore` 에 들어 있습니다. 절대 커밋하지 마세요.

## 실행

```bash
python -m bot.main
```

마이그레이션을 안 돌린 채 실행하면 없는 테이블 이름과 함께 `alembic upgrade head` 를 안내하고 종료합니다.

## 커맨드

봇 안에서 `/명령어` 를 치면 아래 목록이 그대로 나옵니다.

### 도움말

| 커맨드 | 설명 |
| --- | --- |
| `/명령어 [공개]` | 쓸 수 있는 커맨드 전부 보기 (기본은 나만 보기) |

### 파티 일정

| 커맨드 | 설명 |
| --- | --- |
| `/파티등록 보스 난이도 시각 [고정] [요일] [날짜] [파티원]` | 파티 일정 등록 |
| `/파티목록` | 다음 실행 시각이 빠른 순으로 나열 |
| `/내일정 [캐릭터]` | 그 캐릭터가 들어가 있는 파티만 조회 |
| `/파티수정 일정` | 시각·요일(날짜)·파티원을 고치는 모달 |
| `/파티삭제 일정` | 확인 버튼을 거친 뒤 비활성화 |

- 보스는 autocomplete로 고르고, 난이도는 **그 보스에 실제로 있는 것만** 제안됩니다.
- **`고정` 을 끄면 1회성 파티**입니다. `날짜` 에 `2026-09-10` 처럼 적고, 정시 알림이 나가면 자동으로 사라집니다.
- 고정 파티는 `요일` 로 매주 반복합니다. **검은 마법사만 월간**이라 `날짜` 에 `15` 처럼 일자를 적습니다.
- `파티원` 을 비우면 **등록된 캐릭터 목록에서 드롭다운으로 고릅니다.** 직접 적고 싶으면 콤마로 구분해 넣으면 되고, 미등록 이름은 **미연결 캐릭터**로 자동 생성됩니다.

### 캐릭터

| 커맨드 | 설명 |
| --- | --- |
| `/캐릭터등록 이름 [대표]` | 내 디스코드 계정에 캐릭터 연결 |
| `/캐릭터목록 [유저]` | 등록된 캐릭터와 참여 파티 수 |
| `/캐릭터수정 캐릭터 [새이름] [대표]` | 이름 변경 / 대표 지정·해제 |
| `/캐릭터삭제 캐릭터` | 확인 버튼을 거친 뒤 삭제 |

캐릭터에 연결한 디스코드 계정이 **알림에서 멘션되는 대상**입니다.
남의 캐릭터는 서버 관리 권한이 있어야 고치거나 지울 수 있습니다.

### 수익 정산

| 커맨드 | 설명 |
| --- | --- |
| `/수익 [캐릭터] [주차]` | 이번주/지난주 결정석 수익 정산 |
| `/클리어 보스 난이도 [캐릭터]` | 이번 주기 클리어 기록 |
| `/클리어취소 보스 난이도 [캐릭터]` | 클리어 기록 삭제 |
| `/결정석 보스 난이도 [인원]` | 보스 결정석 시세와 인원별 분배액 |
| `/파티수익 일정` | 그 파티의 총 결정석값과 1인 분배액 |

`/수익` 에서 캐릭터를 비우면 대표 캐릭터를, 대표가 없으면 내게 연결된 전 캐릭터를 합산합니다.

### 관리

| 커맨드 | 설명 |
| --- | --- |
| `/알림채널 채널` | 파티 알림 채널 지정 (서버 관리 권한 필요) |
| `/알림설정확인` | 현재 알림 설정 확인 |

## 도메인 규칙

### 주기·리셋

- **주간 리셋은 매주 목요일 KST 00:00** 입니다. 수요일 23:59와 목요일 00:01은 서로 다른 주입니다.
  ISO 주차를 그대로 쓰지 않고, 그 시각이 속한 주의 **시작(가장 최근 목요일 00:00)** 을 찾아
  그 날짜의 ISO 주차를 주차 키로 씁니다. ISO 주차는 그 주의 목요일이 결정하므로 두 값이 일치합니다.
- **월간 리셋은 매월 1일 KST 00:00** 입니다. `period_key` 는 주간이면 `2026-W37`, 월간이면 `2026-09`.
- 월간 일정의 `날짜` 가 그 달의 마지막 날보다 크면 마지막 날로 맞춥니다. (31일 지정 + 2월 → 28/29일)

### 결정석 분배

1. 보스명과 난이도를 **공백 제거 + 소문자화** 로 정규화해 `보스#난이도` 키를 만듭니다. (`반 레온` → `반레온`)
2. 분배 인원수는 이 순서로 정합니다.
   - 대상 캐릭터가 파티원에 포함된 일정이 있으면 → 그 일정의 인원수
   - 없지만 같은 보스·난이도 일정이 있으면 → 그중 첫 번째 일정의 인원수
   - 아무 일정도 없으면 → 1인(솔로)
   - **시즌 보스는 파티 일정이 있어도 항상 1인** 입니다. (정규화된 이름에 `시즌보스` 또는 `메이린` 포함)
3. 나눗셈은 전부 **정수 나눗셈(내림)** 입니다. 솔 에르다 기운도 같은 인원수로 나눕니다.
4. 계산에는 결정석값만 넣습니다. 드랍 아이템 등 부가 수익은 범위 밖이라 임베드에 그 사실을 적습니다.
5. **주간 결정석 판매 개수 상한은 구현하지 않습니다.** 원본 앱과 같이 상한 없이 단순 합산합니다.

시세가 바뀌면 `bot/domain/boss_data.py` 의 `BOSS_REWARDS` **한 곳만** 고치면 됩니다.
다른 코드에는 시세 숫자가 없습니다.

## 알림

1분 간격 루프가 활성 일정을 훑어 **일정 30분 전**과 **일정 정시**에 알림 채널로 임베드를 보냅니다.
파티원 중 디스코드 계정이 연결된 사람은 멘션합니다.

임베드 형식은 이렇습니다.

```
[썸네일] NORMAL 카링
        ⏰ 25분 뒤 보스 파티

        난이도   노멀 (NORMAL)
        반복     1회성
        시간     2026-09-09(수) 21:00 · 25분 후
        파티원   ・본캐 — @유저
                ・부캐 — @유저
        예상 1인 분배  3억 3900만
```

썸네일은 **보스 34종 전부 기본으로 들어 있습니다.** `bot/domain/boss_data.py` 의
`BOSS_IMAGES` 가 나무위키 문서 [메이플스토리/보스 몬스터](https://namu.wiki/w/메이플스토리/보스%20몬스터)
의 보스별 썸네일을 가리킵니다.

**사진은 코드로만 관리합니다.** 디스코드에서 바꾸는 커맨드는 두지 않았습니다.
나무위키 CDN을 직접 참조하는 방식이라 문서가 갱신되면 주소가 바뀌어 사진이 깨질 수 있는데,
그때는 `BOSS_IMAGES` 의 해당 줄만 고쳐서 배포하면 됩니다. 이미지 저작권은 넥슨에 있습니다.

**1회성 파티는 정시 알림이 나간 뒤 비활성화**됩니다. 봇이 꺼져 있는 동안 시각이 지나간
1회성 일정은 1시간이 지나면 알림 없이 목록에서만 치웁니다.

**스케줄러로 `discord.ext.tasks` 를 골랐습니다** — 1분 폴링이면 충분한데 봇 라이프사이클
(연결 대기, 종료 시 정리)에 그대로 얹히고 APScheduler 의존성이 하나 줄기 때문입니다.

### 중복 발송을 막는 방법

`NotificationLog` 의 `(schedule_id, kind, occurrence_key)` **유니크 제약**이 유일한 방어선입니다.
`occurrence_key` 는 예정 시각을 분 단위로 찍은 문자열(`2026-09-10T21:00`)이고,
`kind` 는 `pre30` / `ontime` 입니다.

발송 순서가 중요합니다 — **기록을 먼저 커밋하고, 성공했을 때만 메시지를 보냅니다.**
이미 보낸 회차면 INSERT가 유니크 제약에 걸려 그 자리에서 멈춥니다. 그래서 봇을 재시작하거나
루프가 겹쳐 돌아도 같은 회차는 한 번만 나갑니다. (반대 순서였다면 발송 후 기록 실패 시 중복이 납니다.)

봇이 꺼져 있던 동안 지나간 알림은 되살리지 않습니다. 정시 알림은 **예정 시각 ±2분 이내**일 때만
보내므로, 몇 시간 뒤에 켜도 밀린 알림이 몰리지 않습니다.

알림 채널이 설정돼 있지 않으면 조용히 건너뛰고 경고 로그만 남깁니다.

## 설계 결정

사양에 없거나 애매해서 기본값으로 정한 것들입니다.

- **Python 3.11 이상으로 잡았습니다.** 사양은 3.12+였지만 개발 환경에 3.11.9만 설치돼 있어
  3.11에서 도는 코드로 작성하고 실제로 테스트를 돌렸습니다. 3.12에서도 그대로 동작합니다.
- **`bot/cogs/common.py` 를 추가했습니다.** 사양 구조에는 없지만 party/income/admin 세 코그가
  같은 조회 로직(캐릭터 찾기, 일정 조회, autocomplete)을 써서 중복을 피하려고 뒀습니다.
  discord 의존성이 있으므로 `domain/` 이 아니라 `cogs/` 아래입니다.
- **`/수익` 은 주차 키와 월 키를 함께 조회합니다.** 검은 마법사만 월간 키로 기록되는데,
  주차만 보면 정산에서 빠지기 때문입니다. 월 키는 그 주가 속한 달을 씁니다.
- **1회성 파티는 hard delete가 아니라 `is_active=False` 입니다.** 과거 클리어 기록이
  그 일정을 참조할 수 있어서, 목록에서 사라지되 이력은 남깁니다.
- **보스 사진은 코드에만 둡니다.** 서버 관리자가 디스코드에서 바꿀 수 있게 하면 깨진 주소나
  엉뚱한 이미지가 들어갈 수 있어서, 개발자가 배포로만 바꾸도록 했습니다. 34종 모두 URL이
  이미지로 응답하는지 확인하고 넣었습니다(Referer 없이 HTTP 200).
- **`/명령어` 목록은 커맨드 트리에서 자동으로 만듭니다.** 목록을 손으로 적어두면
  커맨드를 늘릴 때마다 문서와 실제가 어긋나기 때문입니다. 코그별로 묶어 보여줍니다.
- **`/알림설정확인` 을 추가했습니다.** 사양의 관리 커맨드는 `/알림채널` 뿐이지만,
  설정이 됐는지 확인할 방법이 없으면 알림이 안 올 때 원인을 못 찾습니다.
- **30분 전 알림은 남은 시간이 30분 이하가 된 첫 순간에 보냅니다.** 봇이 그 구간에 재시작돼
  정확히 30분 시점을 놓쳐도 알림이 통째로 사라지지 않게 하려는 것이며, 제목에는 실제 남은
  시간을 적습니다(예: "21분 전"). 정시 알림과 달리 예정 시각이 아직 오지 않았으므로
  "밀린 알림 되살리기"에 해당하지 않습니다.
- **동기 SQLAlchemy 세션을 씁니다.** SQLite 로컬 파일 기준으로 쿼리가 짧아 이벤트 루프를
  막는 시간이 무시할 만하고, 비동기 드라이버보다 코드가 단순합니다.
- **모든 커맨드는 서버 전용(`guild_only`)입니다.** 모든 데이터가 `guild_id` 로 격리되는데
  DM에는 `guild_id` 가 없기 때문입니다.
- **`/파티삭제` 는 soft delete(`is_active=False`)입니다.** 과거 클리어 기록이 참조하는
  일정을 실제로 지우면 정산 이력이 깨집니다.
- **`alembic.ini` 는 ASCII로만 작성했습니다.** alembic이 이 파일을 시스템 로케일 인코딩
  (한국어 Windows에서는 cp949)으로 읽어서, 한글 주석이 있으면 `UnicodeDecodeError` 로 죽습니다.
  한글 주석은 `alembic/env.py` 에 뒀습니다.
- **자동 마이그레이션은 하지 않습니다.** 기동 시 테이블 존재 여부만 확인하고, 없으면
  `alembic upgrade head` 를 안내하며 종료합니다.

## 범위 밖
